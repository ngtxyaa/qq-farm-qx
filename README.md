# QQ经典农场 · Code 抓取（Quantumult X）

手机 QQ 打开「QQ经典农场」时，把登录用的一次性 `code` 抓下来，自动传进面板并让账号上线。

只读旁路：不改请求、不改响应、不伪造流量。

> 仓库：`ngtxyaa/qq-farm-qx`，分支 `main`。下面的两条订阅地址可直接使用。

## 安装

**两步，都不用手写规则。**

### 1. QX 添加一条远程重写

设置 → 重写 → 引用 → 右上角 `+`，粘贴：

```
https://raw.githubusercontent.com/ngtxyaa/qq-farm-qx/main/qqfarm.rewrite.conf
```

资源标签填 `QQ农场`，保存后打开开关。MITM 域名、抓取规则、脚本地址都在这个文件里，
QX 会自动同步，**不需要你手动添加 `[mitm]` 或往本地塞脚本文件**。

> **脚本位置必须是完整的 `https://` 地址。**
> 写成裸文件名（`qq-farm-code.js`）时，QX 会去手机本地找这个文件——从此仓库里改什么都不生效。
> 这个坑特别费时间，因为表面现象是「code 照样能抓到，但新功能、日志全都没有」，
> 看起来像脚本写错了，实际是手机压根没在用仓库里那份。

### 2. BoxJs 添加订阅

BoxJs →「应用」→「添加订阅」，粘贴：

```
https://raw.githubusercontent.com/ngtxyaa/qq-farm-qx/main/qqfarm.boxjs.json
```

打开「QQ经典农场 · 抓码设置」，填面板地址（例 `http://你的服务器IP:3007`）、管理员账号、密码，打开「抓到后自动上传」，保存。

改完即生效，不用重启 QX、不用重装脚本。

> 订阅卡片上的图标来自仓库里的 `icon.svg`（订阅级 `icon` 字段）。如果图标是灰底字母占位，
> 说明 BoxJs 缓存了旧的订阅文件：在订阅列表里左滑这一条 → 更新，或者删掉重新添加。
> 图标只影响显示，跟抓码、上传无关。

### 3. QX 开三件事

设置 → 重写 **打开** ／ MITM → 生成证书 → 安装到 iOS ／ 设置 → 通用 → 关于本机 →
证书信任设置 → 打开 QX 证书开关。

少了第三步，HTTPS 不会被解密，脚本一次都不会触发。

## 用起来是什么样

1. 手机 QQ 打开「QQ经典农场」
2. 通知弹出「**QQ农场 Code 已上传**」
3. 面板里对应账号自动重新登录并上线

没开自动上传时通知是「Code 已捕获」，长按复制，去面板「添加账号 → Code 页签」粘贴。
code 一次性、分钟级有效，重进小程序会刷新。

每次抓完，BoxJs 里「QQ经典农场 · 抓码设置」最下面两项会自动更新——**最近一次结果**和**运行日志**，出事直接点开看，不用去 QX 日志页翻。

## 自检（不用开 QQ，也不用管 BoxJs）

Safari 打开：

```
https://gate-obt.nqf.qq.com/prod/ws?platform=qq&ver=1.0.0_20260101&code=QXTEST-0000-1111-2222
```

会**连弹两条通知**：第一条标题带版本号，形如 `QQ农场自检 v5.20261113c · 脚本在跑`，内容是存储读写回测 + 配置快照；第二条是最近 5 条日志。这条路径不上传、不改任何配置，纯粹用来确认脚本状态。

> **标题里的版本号是判断「手机上到底跑的是哪一版」的唯一可靠依据。**
> 标题不带版本号、或者只弹一条「Code 已捕获」，说明 QX 加载的仍是缓存里的旧文件——跟配置、跟面板都无关，按「更新脚本」那一节把资源换掉再试。

读法：

| 现象 | 结论 |
|---|---|
| 两条都弹，标题带 `v5` | 跑的是最新脚本。上传还有问题就看第一条里的 enabled、baseUrl、pass |
| 只弹一条「Code 已捕获」 | QX 用的是缓存旧文件，自检分支那版根本没被加载 |
| 两条都弹但「写读回测 失败」 | 脚本能跑、`$prefs` 写不进去，日志栏必然是空的 |
| 一条都不弹 | 脚本没被触发：远程重写没启用 / 没更新，或 MITM 没开、证书没信任。跟 QQ、跟面板都无关 |
| 弹了但写「缓冲 0 条」 | 脚本在跑，只是还没抓到过真实 code——问题在抓取条件，不在上传 |
| 弹了且列出日志 | 一切正常，日志内容与 BoxJs 里那栏一致 |

## 开了自动上传没反应，先看日志

脚本默认**全链路打日志**，每一步都留痕。看日志有几条路，**第 1 条就够用**：

**1. BoxJs 里直接看（最省事，不用开 QX）**

BoxJs →「应用」→ 打开「QQ经典农场 · 抓码设置」，表单最下面两项就是日志：

| 项 | 内容 |
|---|---|
| **最近一次结果** | 一行结论，如 `11-13 16:39 上传成功 HTTP 200 · QQ农场` |
| **运行日志（只读）** | 最近 20 条流水，新→旧，带「最后触发」和命中的域名 |

抓完码回到这一页（退出再进一次）就能看到最新的。看到的是旧内容时，退出本页重进即可刷新。

日志长这样：

```
最近结果 11-13 16:39:14 上传成功 HTTP 200 · QQ农场
最后触发 11-13 16:39:14 gate-obt.nqf.qq.com 抓到=是
-------------- 最近日志（新→旧） --------------
11-13 16:39:14 上传成功，已记录
11-13 16:39:14 上传响应 200 720ms body={"ok":true,…}
11-13 16:39:14 上传 → POST http://…:3007/api/accounts name=QQ农场 code=a1b2c3d4…
11-13 16:39:14 登录成功 200 380ms token=9f2c1a8e…
11-13 16:39:14 无缓存 token，先登录
11-13 16:39:14 配置 enabled=on baseUrl=http://…:3007 user=admin pass=已填(8位) token=无 mode=name name=QQ农场
11-13 16:39:14 抓到 code=a1b2c3d4… len=32 openid=…f3a2 ver=3.2.1_20261113
```

> 这两项是**只读展示**，脚本每次抓码自动覆盖。手动改动会被下一次抓码冲掉，不用管它。

**2. 脚本在 QX 里的输出（可选，一般用不到）**

脚本另外还会 `console.log` 一份，位置在 QX **设置页最下面那一组**里——新版叫「调试记录」，旧版叫「调试」，各版本叫法和位置不完全一样，找不到也不影响排查：**日志以 BoxJs 里那两项为准**，内容完全一样。

对照下面这张表定位（BoxJs 流水与 QX 日志格式一致）：

| 看到什么 | 说明问题在哪 |
|---|---|
| 一条都没有 / 「最近一次结果」空白 | 脚本没跑起来：远程重写没启用 / MITM 没开 / 证书没信任 |
| 只有「触发」没有「抓到」，`抓到=否` | 命中的不是网关域名，或 code 没在 URL 里 |
| `配置 enabled=off` | BoxJs 里总开关没打开，或没点保存 |
| `pass=未填` | 密码空着，或 BoxJs 没保存 |
| `登录失败 401` | 账号密码不对；注意首尾空格，连续错 5 次锁 15 分钟 |
| `登录失败 423` | 手机出口 IP 被面板锁了，等 15 分钟 |
| `登录失败 0` | 连不上面板：地址/端口错、手机网络不通、服务没跑 |
| `上传响应 4xx …error` | body 里就是服务端给的原话 |

**3. 一条命令弹出来**

把 `qq-farm-check.js` 加到 `[task_local]`，手动运行，会连弹几条通知：当前配置、面板登录自检结果、上次成功/失败、最近 8 条日志。跑完结论也会写进 BoxJs 的「运行日志」，回头点开就能复查。

**4. 面板侧反证**

登录面板 → 账号日志。脚本上传成功时这里会多一条「通过备注重新登录账号」。没有这条 → 请求根本没到服务端。

> 日志里的 code 只露前 8 位，openID 只露后 6 位，密码只露位数，不会把可用的凭据写进日志。

## code 从哪来

QQ 小程序里 `qq.login()` 拿到 code 后，客户端把它拼在游戏网关的 WebSocket 地址上：

```
wss://gate-obt.nqf.qq.com/prod/ws?platform=qq&os=ios&ver=<版本>_<日期>&code=<CODE>
```

所以抓取点只有一个：这个网关域名的握手请求。

## 文件

| 文件 | 说明 |
|---|---|
| `qqfarm.rewrite.conf` | QX 远程重写（含 MITM 域名与脚本地址） |
| `qqfarm.boxjs.json` | BoxJs 订阅：配置表单 + 只读日志展示 |
| `qq-farm-code-v5.js` | **当前使用的抓取主脚本**（重写规则指向这个文件） |
| `qq-farm-code.js` | 旧文件名，内容停在上一版（没有版本标记），仅为兼容早期已配置的地址保留 |
| `qq-farm-check.js` | 一键诊断：配置、登录自检、上次结果、最近日志 |
| `qq-farm-code-show.js` | 回看最近抓到的 code（可选定时任务） |
| `icon.svg` | BoxJs 订阅图标（128×128，QQ 蓝底白企鹅） |

## 配置项

BoxJs 表单里前九项是配置，存在 QX 的 `$prefs`，脚本每次触发时读：

| 键 | 说明 |
|---|---|
| `qqfarm_cfg_enabled` | 抓到后自动上传的总开关 |
| `qqfarm_cfg_baseUrl` | 面板地址，例 `http://你的服务器IP:3007`（默认留空，需自己填） |
| `qqfarm_cfg_username` / `qqfarm_cfg_password` | 面板管理员账号密码 |
| `qqfarm_cfg_target` | `name` 按备注名 ／ `account` 指定账号 |
| `qqfarm_cfg_accountName` | 账号备注名，同名覆盖 code 并重启，不重复建号 |
| `qqfarm_cfg_accountId` | 指定账号 ID，留空自动退回按备注名 |
| `qqfarm_cfg_platform` | `qq` ／ `wx` |
| `qqfarm_cfg_notify` | 是否弹通知 |
| `qqfarm_cfg_debug` | 是否往 QX 日志页打印详细日志，默认开 |
| `qqfarm_status` | **只读**，脚本写入的「最近一次结果」，BoxJs 里以单行文本展示 |
| `qqfarm_log_view` | **只读**，脚本写入的最近 20 条日志，BoxJs 里以多行文本框展示 |

优先级：BoxJs 设置页 > 旧版 `qqfarm_cfg` JSON > 脚本里 `CFG.panel`。

## 排障

先按「现象」找，第一行是最容易踩的坑。

| 现象 | 处理 |
|---|---|
| **改脚本后完全没反应，通知文案从没变过** | 规则里的脚本位置写成了裸文件名（如 `qq-farm-code.js`），QX 会去手机本地找文件，GitHub 上怎么改都不生效。改成完整 `https://` 地址，并把手机里那份旧 js 改名或删掉 |
| 上面这条改完还是老样子 | QX 里有多条 `nqf.qq.com` 规则（手动加的本地规则 + 订阅来的远程规则并存）。全删掉，只留一条远程的 |
| 抓不到，日志里没有 `[QQFarm]` | 远程重写没生效：确认已开启该资源、MITM 已开、证书已信任 |
| 有 `[QQFarm] 未命中` | 命中了但 URL 里没 code，去 QX 日志页看这行里的 host 与 gateway |
| 上传失败：未配置面板地址 | BoxJs 里「面板地址」空着，填 `http://你的服务器IP:3007` 后保存 |
| 上传失败：未配置面板密码 | BoxJs 里密码没填或没保存 |
| 上传失败：登录失败 | 面板密码错，或 IP 被限流（每分钟 10 次、连续失败 5 次锁 15 分钟） |
| 一个请求都看不到 | QQ 若对网关做证书固定，QX 无法解密，改用面板自带的抓包代理 |

## 与微信版的区别

微信侧有 `expires_at` / `refreshtoken`，可提前换 code；QQ 侧没有，code 失效只能等掉线再抓。

## 更新脚本（改了代码但手机上没变化，看这节）

先做**前置检查**，这一步能排掉八成的「改了没反应」：打开 QX → 设置 → 重写，看那条 `nqf.qq.com` 规则的脚本位置。

- 以 `https://` 开头 → 走远程，继续往下看缓存的问题
- 是裸文件名（`qq-farm-code.js`）→ **QX 在读手机本地文件**，仓库改一百次也没用。把规则删掉，按「安装」那节重新加远程地址；手机里那份旧 js 改名或删掉

确认走的是远程之后，再看缓存。QX 对远程脚本有**独立的缓存层**，缓存键是资源地址。只改文件内容、地址不变，手机上大概率还在跑旧代码——`?v=` 这种查询参数在部分 QX 版本里会被忽略，不要指望它。

已经验证有效的做法是**换文件名**，让路径本身变掉：

1. GitHub 上把新内容存成 `qq-farm-code-v6.js`（v5 → v6 依次递增）。
2. 改重写规则里的地址：

```
^https?:\/\/gate-obt\.nqf\.qq\.com\/ url script-request-header https://raw.githubusercontent.com/ngtxyaa/qq-farm-qx/main/qq-farm-code-v6.js
```

3. QX 里把这条重写规则删掉重新添加（比「更新」更彻底），或者关闭再打开。
4. 用 Safari 打开一次自检链接，看通知标题里的版本号有没有跟着变。

确认线上文件是否已经是新内容（`raw` 有 5 分钟 CDN 缓存，这个地址不受影响）：

```bash
curl -sL https://github.com/ngtxyaa/qq-farm-qx/raw/refs/heads/main/qq-farm-code-v5.js | wc -c
```

两边字节数一致才算推送成功。字节数对不上就先等几分钟，**这时候在 QX 里点多少次更新都没用**。

没生效的典型现象：通知标题不带版本号、日志内容完全没变、还是老版本的提示语。

## 地址拉不动怎么办

`raw.githubusercontent.com` 在国内部分网络下会超时，表现为订阅加不上、或者重写更新后脚本没变化。

三个办法，按顺序试：

1. **让 QX 代理这条域名**：QX 的分流规则里确保 `raw.githubusercontent.com` 和 `github.com` 走代理，然后重开一次 QX。
2. **换网络拉一次**：切到能访问的手机网络或 Wi-Fi，重新更新重写资源；拉成功一次后 QX 会缓存到本地。
3. **换订阅地址的写法**：把 `raw.githubusercontent.com/<用户>/<仓库>/main/<文件>` 换成 `github.com/<用户>/<仓库>/raw/refs/heads/main/<文件>`，两者指向同一份文件，但走的是不同线路，哪条通就用哪条。

拉成功后的校验办法：浏览器打开脚本地址，看开头注释里有没有 `selfTestReport` —— 有就是新版。
